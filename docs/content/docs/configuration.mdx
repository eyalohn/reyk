Reyk has two configuration surfaces: `pyproject.toml` that controls how the CLI vendors dependencies,
and parameters on the `isolate_package()` function that control how isolation is applied at runtime.

## `pyproject.toml` configuration

Add a `[tool.reyk]` section to your `pyproject.toml`:

```toml
[tool.reyk]
libraries-path = "libs"
vendor-groups = ["vendor-libs"]
```

All fields are optional and fall back to their defaults if omitted.

### Options

- **`libraries-path`** (string, default: `"libs"`): Relative path where vendored libraries are installed.
- **`vendor-groups`** (array of strings, default: `["vendor-libs"]`): A list of ` [dependency-groups]` whose packages should be vendored.

## `isolate_package()` configuration

`isolate_package()` is called in your package's **init**.py and installs the import hook at runtime. It accepts a single parameter:

```py
def isolate_package(vendor_package: VendorPackage) -> None:
```

### Parameters

- **vendor_package** - The package to vendor, consists of the following fields:
- **package_name** - Package to isolate - should be like `reyk` or like `reyk.sub_package`
- **vendor_libs_path** - Path to the vendor libs directory (importable by `vendor_libs_import_name`)
- **vendor_libs_import_name** - Optionally specify the import name for the vendored libraries ie: `reyk.libs` or `libs`.
    The default (if `None`) will be the `{package_name}.libs`.
- **context_detection** - Optional `ContextDetectionConfig` containing code locations to ignore for this package.

You can create the vendor_package with get_caller_vendor_package() which will be generated based on your stacktrace
(the caller package name and directory).

## Examples

Calling with all defaults - the common case:

```py
from reyk.isolator import isolate_package, get_caller_vendor_package

isolate_package(get_caller_vendor_package())
```

Calling with a custom libs directory name:

```py
from pathlib import Path
from reyk.isolator import isolate_package
from reyk.isolator_definition import VendorPackage

isolate_package(VendorPackage(package_name="vendor", vendor_libs_path=Path(__file__).parent))
```

```toml
[tool.reyk]
libraries-path = "vendor"
```

## Context detection

Set `context_detection` on the `VendorPackage` to configure locations Reyk should ignore
when determining whether an operation belongs to that package:

```py
from dataclasses import replace

from reyk.config import CodeLocation, ContextDetectionConfig
from reyk.isolator import get_caller_vendor_package, isolate_package

package = replace(
    get_caller_vendor_package(),
    context_detection=ContextDetectionConfig(
        user_ignore_rules=(
            CodeLocation(module="company.plugin_loader"),
        ),
    ),
)
isolate_package(package)
```

`VendorPackage` is frozen. Supply configuration when constructing it, or use
`dataclasses.replace` to customize the package returned by `get_caller_vendor_package()`
before registering it with `isolate_package()`.

Module names match `__name__` or `__spec__.name` exactly; submodules are not included.
File-path-derived names are used only for package ownership, not ignore rules.
Omitting `function` matches all
functions in that module. Function names are definition names such as `find_spec`, without
the class prefix. Use `function="<module>"` to match module-level execution.

Matching locations are skipped for that package, and detection continues to the caller. These rules apply
to imports, `sys.modules` access, and distribution discovery. They also skip imports a
matching function performs for its own dependencies, so select locations accordingly.

Each package has its own configuration. A rule on one package does not allow another
package to look past that location. `ContextDetectionConfig` always includes the built-in
rule for `_virtualenv.find_spec`, in addition to Reyk's existing handling of its own code
and the standard library. Configure additional locations through `user_ignore_rules`.
The read-only `ignore` property concatenates `system_ignore_rules` and `user_ignore_rules`.
`system_ignore_rules` cannot be supplied to the constructor or
changed on the frozen configuration, so an empty `user_ignore_rules` tuple keeps the
built-in rule.

## Keeping both surfaces in sync

The `libraries-path` option in `pyproject.toml` and the `vendored_libs_dir_name` parameter in `isolate_package()` refer to the same directory.

If these two values do not match, the CLI will vendor packages into one directory while the runtime hook looks in a different directory.
Remember to change both values together.
